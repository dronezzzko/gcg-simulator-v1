# Equivalence of the Rust port with the Python reference

The Rust port is behaviourally equivalent to the Python reference (`src/gcg_sim` at `d9d41af`) in
its rules engine, card behaviours and the reference search. This document gives the method, the
evidence, and every known difference with its root cause and impact. Results are filled in from
runs on the golden platform; nothing here is claimed without a run.

## Golden platform

Byte equivalence is defined on one platform, because CPython takes `exp`, `log`, `pow` and
`erfc` from the C library and the Rust port reproduces those calls exactly (W-137):

| Item | Value |
| --- | --- |
| Machine | Apple M2 Pro, macOS 27.2 (26B123), Apple libm |
| Python reference | Python 3.15.1 (uv 0.13.6), commit `d9d41af` |
| Rust | rustc 1.99.1 (LLVM 23.1.1), release profile |

On another platform the engine is still integer-only and equivalent, but the reference search's
floating-point leaf values can differ in the last bit wherever the C library differs.

## Method

1. **Primitives.** `crates/gcg-core/tests/vectors.rs` checks SplitMix64, `derive_seed`
   (SHA-256 of the CPython `repr` of the seed path), float `repr` (shortest digits, ties to
   even), `format(x, ".Nf")`, `round`, CPython's Neumaier `sum()`, libm `pow`/`erfc`/`exp`/`log`
   and `json.dumps` against vectors exported from Python (`port/oracle/export_vectors.py`).
2. **Data and effects.** All 1153 card definitions and the four card-database fingerprints;
   476 deck-validation cases with every violation message; 15,000 Unicode vectors; the effect IR
   exported from the Python registry, with every node and program content id (CPython `repr` of
   the DSL) recomputed in Rust and equal; the 27 golden files regenerated byte for byte.
3. **Differential corpus.** Python game, search, fuzz, coverage, view, world and per-test
   traces (`port/oracle/traces.py`, `pytest_trace.py`) record at every decision the state
   digest, the game RNG, `version`, `action_count`, `event_group`, the rules-check marker, the
   ordered legal options and the chosen action, plus full snapshots at intervals. `gcg-diff`
   replays every trace through the Rust engine and stops at the first divergence with a
   readable diff. The corpus is identical under two Python hash seeds and with Python's
   derived-view cache disabled, so it does not depend on hashing or on the cache.
4. **End to end.** `scripts/compare_python_vs_rust.sh equivalence` runs Python
   `gcg-sim benchmark` and Rust `gcg-eval reference-benchmark` on the same decks, seeds and
   options and compares every output file byte for byte after masking exactly three
   implementation fields (`scripts/normalize_outputs.py`: `versions.package`,
   `versions.code_digest`, `ai.factory`, and their two renderings in `summary.md`);
   `timing.json` is excluded. Each Python baseline is generated under PYTHONHASHSEED 1 and 2
   and must be identical; the Rust run is repeated at `--workers 1`, `4` and `10`.

### Numbering-shift probe (PLAN §8.9, R1)

The reference's equivalent-move fingerprint reads once-per-turn records, and lasting-rule once
keys contain `effect_key`, a number Python assigns in first-use order inside one process
(`effects/registry.py:124-130`). Python's own output could therefore depend on which games a
worker process played before. The probe runs Python with every process-local effect number
shifted by 1,000 (`port/oracle/offset_hook/sitecustomize.py`) and Python at `--workers 1`
against `--workers 10`:

`COMPARE_OUT=build/probe scripts/compare_python_vs_rust.sh equivalence --matches 4 --seeds "1 2"
--formats bo3 --presets "fast standard" --pairs "red-green-zeon:blue-white-federation
purple-white-tekkadan:red-green-zeon" --decision-logs off --offset-probe 1000 --python-only`

Result: 8 configurations, 0 depend on the numbering, and Python `--workers 1` and `--workers 10`
differ in 0 (each baseline also identical under PYTHONHASHSEED 1 and 2). The hazard exists in
the code but did not fire on these games; the Rust port keys continuous effects by value, so it
cannot depend on numbering at all.

## Known differences

None of these changes a game, a decision or a byte of `results.json`, `games.ndjson`,
`replays/*.json` or `summary.md` (apart from the three masked fields).

| # | Difference | Root cause | Impact |
| --- | --- | --- | --- |
| D1 | Error messages that embed CPython exception text (e.g. `GameFailure "…: {TypeName}: {exc}"`, `KeyError` reprs, `JSONDecodeError` details, `strerror`) | The text comes from CPython internals | Rust matches the prefix, the exit code and the file side effects (PLAN A19); tested as prefix relations |
| D2 | A battle-damage redirect cycle (two GD04-095) ends the game with `EngineError::RedirectCycle` instead of Python's `RecursionError` | Python recurses without a cycle guard (W-143) | Same outcome: the game fails and the run exits 1 with no reports; only the message differs |
| D3 | `--matches` and `--replays` above 4,294,967,295 are a usage error (exit 2) | The Rust config stores them as `u32` | Python would accept and try to run them; no realistic run is affected |
| D4 | `gcg-sim replay` of a document whose seed, chooser, action arguments or deck sizes fall outside the simulator's integer types reports a malformed replay (exit 1); non-dict `counts`/`expected` report malformed instead of a traceback (exit 1) | Fixed-width Rust types | Exit code and absence of reports are the same |
| D5 | Replay JSON parsing: serde_json rejects `NaN`/`Infinity` and reads integers above u64 as floats, where Python's `json.loads` accepts them | Different JSON parsers | No file the simulator writes contains them |
| D6 | `timing.json`: `"python": "none (Rust build)"`, `"platform"` is `{os}-{arch}`, and an added `"topology"` key | Rust has no CPython; topology is reported for the Apple-silicon support | `timing.json` is wall-clock data and excluded from every comparison |
| D7 | The derived view keeps keyword amounts in declaration order, not dict insertion order | A fixed array per Unit instead of a dict | Unobservable: the engine and AI only test membership, take `len`, or sort (`ai/values.py:30`, `ai/actions.py:356`); the `testkit.keywords` probe is compared as a mapping, as Python's tests compare it |
