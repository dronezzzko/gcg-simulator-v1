  mechanism, besides P6-K's trailing templates:

### W-104 — resolved by the recorded decision (the lead may override)
- **Decision:** `timing.json` keeps the deterministic `decisions` and `decisions_per_game` as
  its machine-independent work measure, with no CPU-time or start-up-time field:
  - safe std has no CPU-time clock; `getrusage` or `clock_gettime(CLOCK_THREAD_CPUTIME_ID)`
    need `unsafe` libc FFI, which the lints deny outside `crates/gcg-core/src/libm.rs` (§10.6);
  - no safe wrapper crate is in A8's list or the cargo cache (the cache holds `libc`, which is
    `unsafe` to call, and no `nix`, `cpu-time` or similar);
  - a per-worker busy-seconds or start-up measure would be wall time again, needs
    `crates/gcg-runner/src/run.rs` (outside GAP-C's files), and would add another
    non-reproducible number to the one non-reproducible report.
- **Evidence:** `gapc_tools.rs::w75_w76_w104_analysis_scope_block_and_timing_fields` pins
  `gcg-eval benchmark`'s `timing.json` keys (Python's keys, `topology`, `decisions`,
  `decisions_per_game`) and checks `decisions_per_game` against `games.ndjson`'s action counts;
  `p6m_cli.rs::t153_…` checks the same counts. No file changed for W-104.
- **Ablation:** no AI effect (GAP-C common row).
